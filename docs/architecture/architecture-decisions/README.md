# Architecture Decision Records

Store one ADR per material architecture or product-technical decision. Use sequential IDs and do not reuse retired IDs.

## Minimum template
1. **Title and status:** proposed, accepted, superseded, or rejected.
2. **Date and owners.**
3. **Context:** the problem and constraints.
4. **Options considered:** realistic alternatives and trade-offs.
5. **Decision:** what was chosen and why.
6. **Consequences:** benefits, costs, migration impact, and new risks.
7. **Follow-up:** implementation, documentation, tests, and revisit triggers.

When a decision changes, create a new ADR that references the previous one. Keep historical decisions available for context.
