# Product and Accounting Glossary

| Term | Meaning in this project |
|---|---|
| Accounting period | A date range within a financial year to which entries are assigned. |
| Audit log | A record of an important action, actor, target, and time. |
| Chart of accounts (CoA) | The organisation's list of accounts used to classify transactions. |
| Control account | An account whose balance is expected to reconcile to a related subledger or workflow. |
| Credit | The right-hand side of a double-entry posting; its effect on balance depends on account type. |
| Debit | The left-hand side of a double-entry posting; its effect on balance depends on account type. |
| Double-entry accounting | A system where each journal balances total debits and credits. |
| Financial year | The organisation's accounting year, which may differ from the calendar year. |
| General ledger | The detailed record of posted accounting entries by account. |
| Idempotency | A property where repeating an operation does not create an unintended duplicate effect. |
| Journal entry | A dated accounting transaction made up of two or more debit/credit lines. |
| Journal line | One account-level debit or credit within a journal entry. |
| Multi-tenancy | Serving multiple organisations while keeping each organisation's data and permissions separate. |
| Nominal account | An account used to classify financial activity; terminology can vary by accounting context. |
| Posting | The controlled transition that makes a journal affect the authoritative ledger. |
| Reversal | A traceable accounting entry that offsets a previously posted entry. |
| Soft lock | A period restriction that may permit narrowly authorised exceptions; exact policy must be defined. |
| Hard lock | A period state that prevents prohibited changes, subject only to an explicitly governed process. |
| Trial balance | A report of ledger account balances showing debit and credit totals. |
| Tenant | An organisation whose data is logically separated from other organisations. |
| VAT | UK Value Added Tax. Product support and tax treatment must be explicitly specified before any compliance claim. |
