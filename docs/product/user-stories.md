# User Stories

## Organisation and access
- **US-ORG-001:** As an owner, I can create an organisation so that its books are separated from other businesses.
- **US-ORG-002:** As a user who belongs to multiple organisations, I can switch context and see only the selected organisation's data.
- **US-ORG-003:** As an administrator, I can grant roles to members so that access matches their responsibilities.
- **US-ORG-004:** As a viewer, I can inspect permitted reports without being able to change accounting records.

## Chart of accounts and periods
- **US-COA-001:** As a bookkeeper, I can view and maintain eligible nominal accounts while preserving historical references.
- **US-PER-001:** As an accountant, I can define a financial year and its periods without overlapping date ranges.
- **US-PER-002:** As an authorised user, I can lock a period to prevent unauthorised changes to closed books.

## Journals
- **US-JRN-001:** As a bookkeeper, I can save a balanced or incomplete journal as a draft while preparing it.
- **US-JRN-002:** As an accountant, I can validate a journal and receive actionable errors when accounting rules fail.
- **US-JRN-003:** As an authorised user, I can post a validated journal so that it affects the ledger exactly once.
- **US-JRN-004:** As an accountant, I can correct a posted error through a traceable reversal and replacement entry.
- **US-JRN-005:** As an auditor, I can see who created, changed, validated, posted, or reversed a journal and when.

## Reporting
- **US-REP-001:** As an owner, I can view a trial balance for a defined date or period.
- **US-REP-002:** As an owner, I can review profit and loss and balance sheet reports whose totals reconcile to the ledger.
- **US-REP-003:** As a user with report access, I can export data while retaining clear period, currency, and organisation context.

## Story acceptance
Each story must have explicit acceptance criteria, permission expectations, failure cases, and test references in the task backlog before implementation begins. This list is a baseline and should be expanded as product scope is confirmed.
