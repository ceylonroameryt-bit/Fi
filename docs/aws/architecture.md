# Blynt — AWS Cloud Architecture

## 1. Overview
Blynt is a UK-focused multi-tenant double-entry accounting SaaS engineered for precision, regulatory compliance, and high availability. This document defines the production-grade target cloud architecture hosted on Amazon Web Services (AWS) in the London region (`eu-west-2`), aligned with UK data residency requirements.

## 2. Infrastructure Components

### 2.1 Regional Placement & Data Sovereignty
- **Primary AWS Region**: `eu-west-2` (London).
- **Compliance**: All financial ledgers, audit trails, tenant credentials, and uploaded transaction receipts remain strictly within UK jurisdiction under UK GDPR and HMRC record-keeping obligations.

### 2.2 Compute Layer: AWS App Runner
- **Service**: Managed container runtime with automatic TLS termination and autoscaling.
- **Port**: `4000` (Fastify / Express NestJS HTTP engine).
- **Health Check Endpoint**: `/api/v1/health` (HTTP GET, interval: 10s, timeout: 5s, healthy threshold: 1, unhealthy threshold: 3).
- **Autoscaling Baseline (DEV)**: Minimum 1 instance, maximum 2 instances, scaling up at 80 concurrent requests.
- **VPC Egress**: App Runner VPC Connector linked to private subnets to reach RDS PostgreSQL securely without exposing database ports to the public internet.

### 2.3 Relational Database Layer: Amazon RDS for PostgreSQL
- **Engine**: PostgreSQL 16.6.
- **Instance Class (DEV)**: `db.t4g.micro` (2 vCPUs, 1 GB RAM, ARM Graviton2 for high efficiency and minimal cost).
- **Storage**: 20 GB gp3 with storage autoscaling enabled up to 100 GB.
- **Isolation**: Placed inside private subnets across two Availability Zones (`eu-west-2a`, `eu-west-2b`). Publicly accessible: `false`.
- **Encryption**: AES-256 storage encryption using AWS KMS managed key.

### 2.4 Document & Attachment Storage: Amazon S3
- **Bucket**: `blynt-dev-documents` (environment-specific naming).
- **Security**: 100% Public Access Blocked (`aws_s3_bucket_public_access_block`).
- **Encryption**: Server-Side Encryption with Amazon S3 managed keys (SSE-S3).
- **Access Model**: Presigned short-lived URLs (TTL: 900 seconds) generated by `S3StorageProvider` for client-side download/upload.

### 2.5 Security, Secrets, and IAM
- **Secrets Management**: AWS Secrets Manager storing database credentials, 64-character cryptographic JWT signing keys, and session secrets.
- **CI/CD Federation**: IAM OpenID Connect (OIDC) provider for GitHub Actions (`repo:ceylonroameryt-bit/Fi:*`). No long-lived AWS IAM access keys or static credentials in GitHub.
- **Least Privilege**: App Runner execution role restricted to Secrets Manager read and S3 bucket read/write permissions.

### 2.6 Observability & Logging
- **Log Aggregator**: Amazon CloudWatch Logs (`/aws/apprunner/blynt-dev-api`).
- **Log Retention**: 7 days in DEV (30 days in Production) to eliminate unnecessary CloudWatch storage overhead.
- **Redaction**: Strict server-side secret filtering strips sensitive authorization tokens, passwords, and PII before output.
